# 运城扣点点麻将 Web 应用 - 设计文档

日期：2026-08-23（2026-08-27 与代码同步重写）
状态：已批准（用户确认"开始做"）；本文档为与当前代码实现一致的权威版本

## 1. 目标

构建一个可多人联机的运城扣点点麻将 Web 应用，支持创建房间、加入房间、积分、聊天等功能，AI 机器人可在人数不足时补位、断线/超时自动托管代打。功能尽量完善、无明显 bug。当前唯一玩法为 136 张民间通用版（带风带箭，已彻底移除 108 张旧玩法）。

## 2. 技术架构

- 后端：Node.js 单服务（http 模块提供静态页面 + ws 库提供 WebSocket 实时通信），入口 `server.js`
- 前端：原生 HTML/CSS/JS 单页应用（无构建步骤），桌面与手机浏览器自适应（`maximum-scale=1.0` 禁缩放）
- 服务端口：默认 **3100**（`PORT = Number(process.env.PORT || 3100)`，可用环境变量覆盖）
- 部署：`npm install && node server.js`（或 `npm start`）一条命令启动，浏览器访问 `http://localhost:3100`；局域网通过 IP 访问，可配合内网穿透公网联机
- 依赖：仅 `ws` 一个 npm 包（^8.18.0）；麻将规则引擎为纯函数模块，独立可单测
- 运行环境：Node v24.19.0（实测）；独立 Git 仓库，master 分支

## 4. 核心规则（136 张民间通用版，唯一玩法）

1. **牌墙 136 张**：万(w)/条(t)/筒(b) 1-9 各 4 张（27 种 × 4 = 108）+ 东南西北中发白（e/s/x/n/z/f/p）各 4 张（7 种 × 4 = 28），合计 34 种 136 张。
2. **只碰杠不吃**：只能碰、明杠、暗杠、补杠，不能吃牌。
3. **胡牌结构**：4 面子 + 1 将（任意对子），或七小对（含豪华七小对）、十三幺；明牌区（碰/杠刻子）作为已成型面子参与结构计算。
4. **胡牌点数限制**：牌点数 = 数牌按面值（1-9）、字牌一律 10 点。1/2 点不能胡（点炮自摸都不行）；3/4/5 点只能自摸；6/7/8/9/字牌（10 点）可点炮可自摸。
5. **开局暗扣 1-4 点（默认开启）**：每人开局从 1/2/3/4 中暗选一个作为本局胡牌倍数（弹窗展示手牌供参考），全部选完后庄家摸第 14 张正式开局；选点对所有人公开显示。AI/托管/断线/超时座位自动随机补 1-4 点，保证不卡扣点阶段。房间可关闭扣点（关闭后本局倍数固定 ×1）。
6. **报听（听口）规则**：房间 `allowTing` 固定开启（136 必选核心规则，不可关闭）。
   - 报听时机：摸牌后（14 张）或碰后立即（11 张，碰完即听不待下轮摸牌）。
   - 报听硬性条件：打出某张后仍听牌，且听口列表至少含一张 ≥6 点牌（6/7/8/9/字牌=10 点）。
   - 报听动作：打出被扣的牌暗入废牌堆（渲染为牌背，不参与任何碰/胡响应判定），手牌锁定。
   - 报听后行为：摸牌即打（系统自动打出刚摸的牌）；可自摸胡（受点数限制）或选择过牌；禁碰，只可杠。
   - 报听后禁杠听张：明杠/补杠/暗杠若会破坏听口一律拒绝（杠牌在当前听口中则不允许），非听张杠不受影响；杠后补牌继续锁死摸打。
   - 听口提示：出牌阶段手牌角标显示"打出某张后可胡的张数（4-已见张数）"，仅提示满足 ≥6 点硬性条件的可报听项；选牌阶段不可报听牌置灰并提示。
7. **番型倍数（乘法叠加）**：
   - 平胡 ×1；碰碰胡 ×2；七小对 ×4；豪华七小对 ×8；杠上开花 ×2（自摸且上一动作是杠）。
   - 开关型番型（默认关闭，开启时倍数可配）：清一色 ×4（默认，手牌+明牌区全部同花色且无字牌）、一条龙 ×4（默认，手牌+明牌区同一花色 1-9 齐全）、十三幺 ×8（默认，14 张 = 13 种幺九牌各 1 张 + 其中 1 种成对，须无明牌区）。
   - 十三幺优先于七对/碰碰胡判定；平胡仅在其他番型都不满足时记名。
8. **计分公式**：点数 × 牌型倍数 × 自己扣点。
   - 点炮胡 = 点数 × 倍数 × 扣点，由点炮者支付。
   - 自摸 = 点数 × 2 × 倍数 × 扣点，三家各自向胡牌者支付一份。
   - 抢杠胡算点炮（按点炮公式，由补杠者支付），且抢杠成立时杠钱不结算。
   - 包胡（一包三）：未报听者打出 ≥6 点牌被报听者胡 → 点炮者赔三家全部分数（相当于 3 份自摸），另两家不出分。
   - 杠分即时结算（杠时入账，不等胡牌）：明杠/补杠 = 该牌点数（字牌 10 点）、暗杠 = 点数 × 2，再乘杠主本局扣点，其余三家各付一份给杠主。
9. **流局荒庄**：牌墙剩 6 墩（12 张）无人胡牌即流局；流局无分差（杠分已在杠时即时入账），公开听牌者名单、全员暗扣、杠分明细与全部手牌。
10. **庄家流转**：上局胡牌者坐庄（谁胡谁坐庄）；流局按房间设置流转（`dealerFlow=keep` 连庄 / `next` 下家接庄，默认下家接庄）；首局随机定庄。

## 6. 功能清单

### 玩家
- 输入昵称（1-12 字）进入大厅，昵称与 playerId 存 localStorage，断线自动重连恢复座位
- 在线/离线/托管状态、房间内座位与玩家信息展示

### 大厅
- 创建房间（4 位数字房间号随机生成）
- 按房间号加入，或从房间列表选择（列表显示状态/人数/创建者/136张带风带箭/AI补位/报听必开/总局数）

### 房间
- 房主：开始游戏、添加 AI、解散房间；非房主：退出房间（牌局进行中不可退出）
- 4 人满自动开局；人数不足时房主点开始（AI 补位开启时自动补满 4 人）
- 总局数打完后进入结算状态：房主可「再来一轮」（重置积分与局数）或解散
- 房间内积分榜（本局/累计）、牌局日志（私有日志按视角脱敏）、聊天（上限 50 条）

### 牌局
- 洗牌发牌（每人 13 张，庄家开局扣点后摸第 14 张），首局随机定庄，之后谁胡谁坐庄/流局按设置流转
- 回合：摸牌 → 出牌 → 其他玩家碰/杠/胡/过响应判定（响应按座位就近优先：胡 > 杠 > 碰）
- 碰、明杠、暗杠、补杠；杠后补牌（可杠上开花）
- 补杠触发抢杠胡判定（抢杠胡算点炮，受点数限制，杠钱不结）
- 自摸判定、报听判定与摸牌即打、听口角标提示、新摸牌视觉标志
- 流局荒庄（剩 6 墩），公开听牌者/扣点/杠分/手牌
- 牌局日志（操作记录，含摸牌隐私脱敏）

### 积分
- 每局胡牌后即时结算（点数 × 倍数 × 扣点），杠分杠时即时入账
- 房间内积分榜（本局/累计）；非最后一局全员确认「确定」后自动开始下一局
- 总局数达到后进入房间结算，可继续新一轮或解散

### AI（src/ai.js）
- 摸牌决策：能胡就胡（受点数限制）→ 满足条件优先报听（保住听口）→ 暗杠/补杠 → 按安全度与保留价值出牌（别人打过的牌优先、保留对子/刻子/相邻顺子）
- 响应决策：胡 > 杠 > 碰（接近听牌时倾向不碰）> 过；报听 AI 同样遵循禁杠听张约束
- AI 补位（aiFill）、断线/超时/托管代打、开局自动扣点

## 7. 通信协议（WebSocket 消息）

- C2S（客户端 → 服务端）：
  - 大厅/连接：`join_lobby`（{name}）/ `reconnect`（{playerId}）
  - 房间：`create_room`（{settings}）/ `join_room`（{roomId}）/ `leave_room` / `start_game` / `add_ai` / `dissolve`
  - 牌局：`play_tile`（{tile}）/ `ting`（{tile}）/ `koupoint`（{points:1-4}）/ `peng` / `gang`（{tile, gangType:'angang'|'bugang'}）/ `hu` / `pass` / `cancel_hosted` / `settle_confirm` / `chat`（{text}）
- S2C（服务端 → 客户端）：
  - `hello`（playerId/name）/ `lobby_state`（rooms）/ `room_state`（room）/ `game_state`（game）/ `action_prompt`（prompt）
  - `settlement`（result + confirms）/ `settlement_confirm`（confirms）/ `draw_notice`（tile）/ `room_notice`（text）/ `chat` / `error`
- game_state 关键字段：roundNo / dealer / turn / stage / wallCount / lastDiscard / drawnTile（仅自己）/ newTile（仅自己）/ kouPoints（全公开）/ kouTiles（报听扣牌一律脱敏为 back）/ gangLogs / tingHints / players（自己手牌可见，他人仅手牌数）/ pending / winners / settings / logs

## 8. 错误处理与健壮性

- 非法操作（不是你的回合、牌不对、重复响应、报听破坏听张等）一律服务端校验并拒绝，返回 `error` 消息
- 断线：60 秒内可重连恢复座位（重连自动补发 game_state / action_prompt / 结算，避免卡局）；断线即标记托管（AI 代打）
- 超时：真人出牌超时 30 秒自动托管；响应窗口 20 秒自动过牌；扣点阶段真人 30 秒未选自动补 1-4 点
- 房主离线：超 60 秒后房主座位 AI 托管打完本局，本局结束自动解散房间（广播 room_notice）
- 并发：单进程事件循环，状态变更全部走服务端校验；AI 代打与真人操作通过 _auto 计数防并发
- 输入校验：昵称长度（1-12）、房间号格式（4 位数字）、扣点取值（1-4）、总局数白名单（0/4/8/12）、倍数范围（1-32）
- 资源上限：MAX_ROOMS=100、MAX_LOGS=200、MAX_CHAT=50
