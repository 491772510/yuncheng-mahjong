# 西安红中麻将玩法设计文档（2026-09-30）

## 1. 目标

在现有运城扣点点麻将 Web 应用中新增「西安红中麻将」玩法：

- 创建房间时通过下拉框选择玩法（扣点点 / 红中麻将），**不同玩法展示不同的配置开关**；
- 扣点点玩法保持现有逻辑与开关完全不变；
- 红中麻将按本设计实现。

## 2. 牌具（112 张）

- 万、筒、条（1-9）各 4 张 = 108 张
- 红中 4 张（万能癞子）
- **无**东南西北、白板、发财
- 庄家 14 张，闲家 13 张

### 牌编码约定

现有扣点点牌编码为 `w1/t1/b1` 格式（万/筒/条）。红中麻将新增编码 **`z0`**（suit=z, rank=0），

- `createTiles112()` 生成 112 张：`w1..w9, t1..t9, b1..b9` 各 4 + `z0` × 4
- `suitOf('z0')='z'`、`rankOf('z0')=0`、`tileName('z0')='红中'`
- 前端 `tileHtml` 需支持 `z0` 渲染（红中牌面：红底/红色「中」字，与扣点点字牌区分）

## 3. 红中癞子规则（核心）

1. 红中 = 万能癞子，可替代任意万/筒/条，用于凑**顺子、刻子、将**。
2. 红中本身可以**碰、可以杠**（红中杠）。
3. **限制**：不能拿红中代替别的牌去碰/杠；只能用红中本身碰杠（即碰/杠的对象必须是真实红中牌）。
4. 天胡特权：**起手 4 张红中，直接胡牌**（开牌即胡，无需等待）。

### 癞子胡牌判定

`checkHuHongZhong(hand, melds)`：

- 将红中（z0）从 hand 中全部抽出，数量记为 `wildCount`；
- 对剩余牌 + melds（明刻/明杠已固定，不可被红中替代补成）做 3n+2 分解：
  - 将牌（一对）：优先普通将；二五八将开关开启时，平胡的将牌必须为 2/5/8（万/筒/条），大胡（清一色/碰碰胡）不受限制；
  - 剩余组成顺子或刻子；每缺一张可用一张红中补齐（红中不能在同一位置重复使用两次以上，受 wildCount 约束）；
- 回溯枚举红中的分配（补顺/补刻/补将），任一路径成功即可胡；
- 七小对 / 龙七对判定需兼容红中：红中可当任意牌凑对，龙七对 = 4 张相同牌的七对（含红中充当）。

### 可胡牌型

平胡、碰碰胡、七小对、龙七对、清一色、混一色。

## 4. 行牌操作

- 可碰、明杠、暗杠、补杠；**禁止吃牌**。
- 杠后必须从牌墙末尾补一张牌。
- 优先级：**胡 > 杠 > 碰**（同一张牌多人响应时按此顺序结算）。
- 红中牌参与行牌时走特殊分支：碰/杠红中本身合法；点炮若打出的牌被红中胡（红中当该牌）——按胡牌模式规则判定。

## 5. 胡牌方式（房间开关，二选一）

- **选项 A【陕西推倒胡模式】**：支持 点炮胡 + 自摸胡 + 抢杠胡。
- **选项 B【纯红中癞子模式】**：只能 自摸 + 抢杠胡，**不许点炮**（别人打出的牌即使能胡也不能胡）。

### 抢杠胡规则

- 只允许抢**补杠**（补杠那张牌），暗杠不能抢。
- 多人同时抢杠支持**一炮多响**（本房间如已开启，多响时按座位顺序依次胡，各算各的）。
- 被抢杠玩家**包三家分**（被抢者一人承担三家应付的分数，经典包牌）。

## 6. 番数计分（红中麻将）

基础底分：1 分。总番 = 下列各项相加；**倍数 = 2^总番**；得分 = 底分 × 倍数。

| 项 | 番数 |
| --- | --- |
| 自摸 | +1 |
| 点炮 | 不加番 |
| 门清（全程没碰、明杠） | +1 |
| 七小对 | +2 |
| 龙七对 | +3 |
| 碰碰胡 | +2 |
| 混一色 | +2 |
| 清一色 | +4 |
| 明杠 | +1 |
| 暗杠 | +2 |
| 红中杠 | +2 |
| 抢杠胡 | 按自摸算番，被抢杠玩家全包 |

### 下炮子（开关，可自由开关）

- 开局前（发牌后、行牌前）玩家可选择**是否下炮**（默认可下 1 个炮；炮注 = 1 分）。
- 下炮玩家**单独多一份输赢，独立于基础胡分，不参与番数相乘**：
  - 下炮者胡牌：其余三家各额外给 1 分/炮；
  - 下炮者输牌（本局非胡方）：向胡家额外付 1 分/炮；
  - 流局不下炮结算。
- 实现为独立结算行，与胡分并列展示。

### 扎码（开关，可自由开关；开房选 1/2/4/6 码）

- 胡牌之后翻码：从牌墙末尾按码数翻牌（码张 = 胡牌后牌墙剩余区翻 N 张，或按本房间已有翻牌逻辑实现）。
- 中码牌：**1、5、9 万/筒/条 + 红中**。
- 每张中码使该胡的得分翻倍（×2 / 码）。
- 与下炮子独立叠加。

## 7. 坐庄与流局（荒庄）

- 谁胡谁坐庄；庄家胡则**连庄**。
- 流局（牌墙摸完无人胡）：**庄家继续坐庄**（不换庄）。
- 即红中玩法固定「胡者坐庄 / 流局连庄」，不走扣点点的下家接庄配置。

## 8. 创建房间与设置

`settings.variant`：`'koudian'`（默认） | `'hongzhong'`。

### 扣点点房间开关（保持现状）

- 总局数（0/4/8/12）、AI 补位、清一色/一条龙/十三幺等倍数开关、报听、扣点等——不变。

### 红中麻将房间开关

- 总局数（0/4/8/12）、AI 补位；
- 胡牌模式：A（推倒胡）/ B（纯自摸+抢杠）；
- 二五八将：开/关（普通平胡必须 2/5/8 当将，大胡不受限）；
- 下炮子：开/关；
- 扎码：关 / 1码 / 2码 / 4码 / 6码。

## 9. 前端改动

1. 创建房间弹窗顶部加「玩法」下拉框（扣点点 / 红中麻将），切换时动态显示对应开关区。
2. 房间视图显示玩法标签（如「红中麻将」），大厅房间卡片也显示玩法名。
3. 红中玩法：发牌后行牌前显示「下炮」选择（若开关开启）；胡牌结算页显示：番数明细（自摸/门清/牌型/杠）、倍数、炮钱、码钱、支付明细。
4. `tileHtml` 支持 `z0` 红中牌面渲染。
5. 气泡/侧栏/语音等既有功能不受影响。

## 10. 服务端与 AI

- `game.js` 按 `room.settings.variant` 分支：发牌（112 张）、癞子胡判定、碰/杠/胡流程（红中特殊）、抢杠（只补杠、一炮多响、包三家）、下炮、扎码、坐庄、番数结算。
- `rules.js` 新增红中麻将判定模块（`checkHuHongZhong` / `canPengHongZhong` / `canGangHongZhong` / 番数计算 / 中码判定等），**不修改扣点点现有函数行为**。
- `ai.js` 适配红中玩法：癞子利用（优先用红中补顺/刻/将）、下炮策略（简单策略：默认不下或按 AI 难度）、行牌正确性（不违规用红中碰杠）。
- 结算数据沿用现有 `payments` 结构扩展：`payments` 增加 `kind:'pao'`（炮钱）与 `kind:'zhaba'`（码钱）行，或并入 hu 明细行注明。

## 11. 测试要求

- `test/rules-hongzhong.test.js`：112 张牌具、癞子胡判定（含红中补顺/刻/将、七小对/龙七对、清一色/混一色/碰碰胡）、二五八将开关、天胡（4 红中）、不能红中代碰杠、抢杠仅补杠、一炮多响、番数计算、中码判定。
- 现有 `npm test` 全部通过（扣点点回归不受影响）。
- 服务验证：`node --check`、启动后 `npm test`、端口探活、git 提交。

## 12. 验收要点（主 Agent）

- 创建房间下拉可选玩法，开关随玩法切换；
- 红中房间可完整打完一局：碰/杠/胡/抢杠/下炮/扎码/坐庄流转正确；
- 结算页展示番数明细与支付明细；
- 扣点点玩法回归无变化。
