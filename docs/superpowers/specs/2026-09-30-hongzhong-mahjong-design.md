## 1. 目标

在现有运城扣点点麻将 Web 应用中新增「西安红中麻将」玩法：

- 创建房间时通过下拉框选择玩法（扣点点 / 红中麻将），**不同玩法展示不同的配置开关**；
- 扣点点玩法保持现有逻辑与开关完全不变；
- 红中麻将按本设计实现。

## 2. 牌具（112 张）

- 万、筒、条（1-9）各 4 张 = 108 张
- 红中 4 张（万能癞子）
- **无**东南西北、白板、发财
- 庄家 14 张，闲家 13 张

### 牌编码约定

现有扣点点牌编码为 `w1/t1/b1` 格式（万/筒/条）。红中麻将新增编码 **`z0`**（suit=z, rank=0），

- `createTiles112()` 生成 112 张：`w1..w9, t1..t9, b1..b9` 各 4 + `z0` × 4
- `suitOf('z0')='z'`、`rankOf('z0')=0`、`tileName('z0')='红中'`
- 前端 `tileHtml` 需支持 `z0` 渲染（红中牌面：红底/红色「中」字，与扣点点字牌区分）

## 3. 红中癞子规则（核心）

1. 红中 = 万能癞子，可替代任意万/筒/条，用于凑**顺子、刻子、将**。
2. 红中本身可以**碰、可以杠**（红中杠）。
3. **限制**：不能拿红中代替别的牌去碰/杠；只能用红中本身碰杠（即碰/杠的对象必须是真实红中牌）。
4. 天胡特权：**起手 4 张红中，直接胡牌**（开牌即胡，无需等待）。

### 癞子胡牌判定

`checkHuHongZhong(hand, melds)`：

- 将红中（z0）从 hand 中全部抽出，数量记为 `wildCount`；
- 对剩余牌 + melds（明刻/明杠已固定，不可被红中替代补成）做 3n+2 分解：
  - 将牌（一对）：优先普通将；二五八将开关开启时，平胡的将牌必须为 2/5/8（万/筒/条），大胡（清一色/碰碰胡）不受限制；
    > ❌ **未实现（规划中）**：代码中不存在"二五八将"判定或开关。实际找将逻辑
    > `_tryPairAsEyeWithWild`（`src/rules.js:598-622`）**任意牌均可作将**，无 2/5/8 约束。
  - 剩余组成顺子或刻子；每缺一张可用一张红中补齐（红中不能在同一位置重复使用两次以上，受 wildCount 约束）；
- 回溯枚举红中的分配（补顺/补刻/补将），任一路径成功即可胡；
- 七小对 / 龙七对判定需兼容红中：红中可当任意牌凑对，龙七对 = 4 张相同牌的七对（含红中充当）。

### 可胡牌型

平胡、碰碰胡、七小对、龙七对、清一色、混一色。

## 4. 行牌操作

- 可碰、明杠、暗杠、补杠；**禁止吃牌**。
- 杠后必须从牌墙末尾补一张牌。
- 优先级：**胡 > 杠 > 碰**（同一张牌多人响应时按此顺序结算）。
- 红中牌参与行牌时走特殊分支：碰/杠红中本身合法；点炮若打出的牌被红中胡（红中当该牌）——按胡牌模式规则判定。

### 抢杠胡规则

> ✅ **已实现**（与本文一致）：抢杠判定只在 `_doBuGang`（`src/game.js:1282`，分支注释 `:1305`「红中：一炮多响」）中触发，
> **暗杠 `_doAnGang`（`:1228`）无抢杠分支**，即暗杠不可抢；被抢杠者按"包三家"独赔。

- 只允许抢**补杠**（补杠那张牌），暗杠不能抢。
- 多人同时抢杠支持**一炮多响**（本房间如已开启，多响时按座位顺序依次胡，各算各的）。
- 被抢杠玩家**包三家分**（被抢者一人承担三家应付的分数，经典包牌）。

## 6. 番数计分（红中麻将）

> ❌ **未实现（规划中）—— 本节的番数表不参与现行结算。**
> 现状：红中已改为**无番（底注 × 中码倍数）制**：底注恒 1 分，
> 自摸每家付 `1×(2 + 中码倍数)`；点炮/抢杠由放炮者（被抢者）**包赔三家** `1×(1 + 中码倍数)×3`，
> 中码倍数 = `2^中码张数`（`src/game.js:1504` 附近 `Math.pow(2, zhaMaCount)`）。
> 结算对象里 `fan: 0`、`noFan: true`、`names: ['无番']`（`src/game.js:1572-1578`），番数**恒为 0**。
> 函数 `calcMultiplierHongZhong` 仍存在于 `src/rules.js:811-876`，但其注释已声明
> 「历史规则，仅保留供规则单测/参考；正式结算已改为无番公式，不再调用本函数」（`src/rules.js:801-803`），
> 且 `src/game.js` 中无任何调用点。

基础底分：1 分。总番 = 下列各项相加；**倍数 = 2^总番**；得分 = 底分 × 倍数。

| 项 | 番数 |
| --- | --- |
| 自摸 | +1 |
| 点炮 | 不加番 |
| 门清（全程没碰、明杠） | +1 |
| 七小对 | +2 |
| 龙七对 | +3 |
| 碰碰胡 | +2 |
| 混一色 | +2 |
| 清一色 | +4 |
| 明杠 | +1 |
| 暗杠 | +2 |
| 红中杠 | +2 |
| 抢杠胡 | 按自摸算番，被抢杠玩家全包 |

### 下炮子（开关，可自由开关）

> ❌ **未实现（规划中）** —— 全项目无"下炮/炮注"流程：设置项中没有 `pao` 字段

> 前端无下炮交互，结算里 `paoGain` 被**硬编码为 0**（`src/game.js:1578`）。
> 下方规则描述仅为设计意图。

（原文）

- 开局前（发牌后、行牌前）玩家可选择**是否下炮**（默认可下 1 个炮；炮注 = 1 分）。
- 下炮玩家**单独多一份输赢，独立于基础胡分，不参与番数相乘**：
  - 下炮者胡牌：其余三家各额外给 1 分/炮；
  - 下炮者输牌（本局非胡方）：向胡家额外付 1 分/炮；
  - 流局不下炮结算。
- 实现为独立结算行，与胡分并列展示。

### 扎码（开关，可自由开关；开房选 1/2/4/6 码）

> ✅ **已实现**：设置项 `zhaMa` 取值 0/1/2/4/6（`src/game.js:2811`），胡牌后从牌墙补抓 N 张，
> 中码牌 = 1/5/9 万筒条 + 红中（`src/rules.js:790` `ZHONG_MA_TILES`），每张中码使得分翻一倍。
> ⚠️ 与本文描述的一处差异：得分**不是"每张中码 ×2 叠乘到胡分上"的简单说法**，而是走
> 「底注 ×(基础手数 + 中码倍数)」公式（自摸基础手数 2、点炮/抢杠 1），见 §6 顶部说明。

- 胡牌之后翻码：从牌墙末尾按码数翻牌（码张 = 胡牌后牌墙剩余区翻 N 张，或按本房间已有翻牌逻辑实现）。
- 中码牌：**1、5、9 万/筒/条 + 红中**。
- 每张中码使该胡的得分翻倍（×2 / 码）。
- 与下炮子独立叠加。

## 7. 坐庄与流局（荒庄）

- 谁胡谁坐庄；庄家胡则**连庄**。
- 流局（牌墙摸完无人胡）：**庄家继续坐庄**（不换庄）。
- 即红中玩法固定「胡者坐庄 / 流局连庄」，不走扣点点的下家接庄配置。
